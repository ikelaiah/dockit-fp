# Implementation plan: v0.9.0 dependable publishing

## Task list

### Slice 1: Release-state diagnostics

1. Add failing tests for unsafe release identifiers, unsafe refs, missing tags
   and a current source that does not match `HEAD`.
2. Harden manifest validation and make release failures corrective.
3. Extend `doctor` with immutable-ref and Pages-workflow readiness summaries.

### Slice 2: Publication workflows and examples

4. Add failing workflow-contract and maintained-example tests.
5. Add backward-compatible single-version workflow inputs and upgrade official
   Pages actions to Node.js 24 majors.
6. Add release-ready single-version and historical examples.
7. Prove repeated historical example builds are byte-for-byte identical.

### Slice 3: Guidance and release

8. Publish the pre-publish checklist and direct 0.x compatibility table.
9. Update Pages guidance, version, changelog, roadmap and release manifest.
10. Run automated, documentation, immutable-release, workflow and review gates.

## Risks and mitigations

| Risk | Mitigation |
| --- | --- |
| Stricter validation rejects a legitimate tag | Accept Git-valid tag paths and full 40-character commit SHAs; test both. |
| New workflow mode breaks existing consumers | Default `versioned` to true and test the existing command path. |
| Workflow input enables shell injection | Pass release text through an environment variable and quote it. |
| Example history becomes nondeterministic | Build a fixed local Git history twice and compare every generated byte. |
