# Implementation Plan: v0.16.1 — Documentation Examples & Dogfooding

## Overview

Repair reader-verifiability gaps in published configuration guidance without
changing DocKit's schema or renderer. Dogfood ordinary identity settings on the
DocKit site and use the existing visual fixture for the banner edge case.

## Architecture decisions

- The DocKit documentation site is the canonical example for `theme.preset`,
  `identity.logo`, `identity.footer` and `identity.links` because those are
  ordinary production settings.
- `examples/visual-fixtures` remains the canonical banner demonstration because
  it already exists to exercise visual states at responsive widths and modes.
- Tests assert the small configuration/asset/result contracts, not whole guide
  prose or screenshots.

## Risks and mitigations

| Risk | Mitigation |
| --- | --- |
| Guide drifts away from rendered examples | Keep config, local asset and guide references under focused tests. |
| Banner becomes a manual review step | Configure the checked-in fixture and build it in tests. |
| Release bump affects old examples | Update only current release references; preserve historical records. |
