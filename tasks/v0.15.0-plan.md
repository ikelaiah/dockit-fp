# Implementation Plan: v0.15.0 — Documentation Audit

## Overview

Add a read-only, deterministic `dockit-fp audit` command that reuses the
configured publication model to find broken local pages, anchors and assets,
then reports a small set of low-noise quality warnings.

## Architecture decisions

- Build one site-level audit model from `load_config`, configured pages, source
  references and `render_markdown` headings; do not validate every finding by
  building a temporary site.
- Use the renderer's `slugify` heading identifiers and the builder's
  source-reference rules, including the root `README.md`.
- Keep diagnostics deterministic: pages in navigation order and findings in
  source order, with stable DK codes and text/JSON formatters.
- Preserve existing `check` semantics. `audit` returns 1 for findings that
  fail its selected policy and 2 only for audit command/configuration errors.

## Risks and mitigations

| Risk | Mitigation |
| --- | --- |
| Audit differs from the generated site | Share page references and heading IDs with existing config/renderer code. |
| Markdown regex audits code blocks | Tokenise fenced sections before extracting inline links/images. |
| Unlisted drafts become noisy | Only report an unlisted Markdown file when a published page links to it. |
| Release actions need remote authority | Complete local release-ready work and report remote steps separately. |
