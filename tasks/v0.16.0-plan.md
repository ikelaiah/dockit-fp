# Implementation Plan: v0.16.0 — Documentation Refinement

## Overview

Align DocKit's published guides, generated configuration, maintained examples
and dogfooded configuration with the released v0.15 contract. Keep the first
site path short, move detail to the relevant reference page, and add small
regression checks for the canonical examples.

## Architecture decisions

- Treat `src/dockit_fp`, its tests and generated `init` output as the source of
  truth; retain legacy behaviour only when the compatibility contract requires
  it.
- Keep the modern recommended layout explicit: `home`, `unlisted: "exclude"`
  and navigation. Show the root-README `source: "root"` form where relevant.
- Keep the beginner guide task-focused. Configuration, audit, GitHub Pages and
  historical-release guides own their detailed reference material.
- Protect structured configuration examples and page-order decisions with
  focused tests instead of brittle whole-document snapshots.

## Risks and mitigations

| Risk | Mitigation |
| --- | --- |
| Documentation hides a compatibility distinction | State the modern recommendation first and identify fallback behaviour explicitly. |
| Prose examples drift again | Parse or assert the few canonical JSON/CLI contracts in tests. |
| Release actions require remote authority | Complete a local release candidate and report the remote PR/tag/Pages steps separately. |
