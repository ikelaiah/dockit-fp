# Implementation plan: v0.11.0 existing-repository adoption

## Overview

Make DocKit-FP safe to introduce into an existing repository: discover only a
root README and Markdown below `docs/`, turn that conservative set into an
editable layout once, and make the resulting configuration authoritative.

## Architecture decisions

- Repository inspection belongs in a small `discovery` module; it does not
  change Markdown and only reads paths under the selected project root.
- A layout page can explicitly select the repository-root `README.md` with a
  narrowly validated source marker. Other root files and traversal remain
  invalid.
- The renderer resolves Markdown links through each page's repository-relative
  source location, which keeps root README links and historical Git archives
  correct without copying documents.

## Risks and mitigations

| Risk | Mitigation |
| --- | --- |
| Discovery publishes unrelated files | Candidate set is strictly root README plus `docs/**/*.md`; tests prove exclusions. |
| Root support weakens containment | Only the exact root `README.md` receives the explicit source marker; all paths are resolved and checked. |
| Historical output reads the checkout | All documents are read from the archived source root passed to the builder. |
| Preview serves invalid output | Validate into a temporary directory before building the serving directory. |
