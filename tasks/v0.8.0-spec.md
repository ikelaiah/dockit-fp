# Spec: v0.8.0 visual-system polish

## Objective

Make Classic, Paper and Midnight deliberate, readable and keyboard-accessible
across long-form documentation and common responsive widths, without adding
remote assets or weakening the shared semantic token contract.

## Scope

- Refine typography, spacing, tables, callouts, code blocks and focus states.
- Add an optional `layout.content_width` choice (`compact`, `comfortable`, or
  `wide`) with default-compatible output.
- Publish a maintained visual-fixture project covering dense prose, tables,
  code, callouts and long documents.
- Document and verify the phone, tablet, desktop, light, dark and visual-theme
  matrix.

## Commands

- Focused: `python -m unittest tests.test_config tests.test_build -v`
- Full suite: `python -m unittest discover -s tests -t . -v`
- Documentation check: `$env:PYTHONPATH='src'; python -m dockit_fp check --root .`
- Fixture build: `$env:PYTHONPATH='src'; python -m dockit_fp build --root examples/visual-fixtures --output build/visual-fixtures`

## Boundaries

- Keep every browser asset local and dependency-free.
- Preserve the default content width for existing schema-version-1 projects.
- Express themes and widths through semantic CSS custom properties.
- Retain native controls, visible focus, reduced-motion support and keyboard
  search/theme flows.

## Success criteria

- All three themes have intentional typography and surface treatment.
- Tables, callouts and code remain readable in light and dark colour modes.
- Content width is validated, documented and reflected in generated markup.
- The maintained fixture builds and covers every visual verification target.
