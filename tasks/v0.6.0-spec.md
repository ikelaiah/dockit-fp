# Spec: v0.6.0 configurable homepage

## Objective

Let a site owner tailor the generated homepage through `docs/dockit.json`,
without editing Python or copied CSS. Existing configurations must render the
same homepage as v0.5.0.

## Assumptions

- The existing schema version remains `1`; the new fields are optional.
- `homepage.sections` controls `capabilities`, `banner`, `introduction`, and
  `release_context`. Omitted values preserve existing behaviour: capabilities
  and introduction are shown, a configured banner is shown, and release
  context is hidden.
- `homepage.capabilities` follows the previously recorded card contract:
  omitted uses the four default cards; an empty list hides the strip.
- Release context is an optional, escaped summary of the build release. It is
  deliberately opt-in so current pages are unchanged.

## Commands

- Focused: `python -m unittest tests.test_config tests.test_build -v`
- Full suite: `python -m unittest discover -s tests -t . -v`
- Documentation check: `$env:PYTHONPATH='src'; python -m dockit_fp check --root .`

## Project structure

- `src/dockit_fp/models.py` holds immutable configuration values.
- `src/dockit_fp/config.py` validates JSON and produces the configuration.
- `src/dockit_fp/build.py` renders homepage-only sections.
- `tests/test_config.py` and `tests/test_build.py` prove the public contract.
- `docs/configuration.md` and `docs/homepage-recipes.md` document supported use.

## Testing strategy

Tests first prove default preservation, configured ordering, empty-strip
behaviour, visibility switches, exact field diagnostics, and HTML escaping.
The focused suite runs during the implementation loop; the full suite gates
the release.

## Boundaries

- Always: preserve defaults, escape configured text, use local assets, and run
  tests before every commit.
- Ask first: add a dependency, change schema version, or change CI/release
  workflow.
- Never: require source edits or copied CSS for homepage configuration.

## Success criteria

- Cards can be replaced, reordered, or hidden using configuration.
- Each homepage section can be explicitly shown or hidden.
- Errors name the exact invalid `homepage` field and a correction.
- A library, application, and API-reference recipe can be copied verbatim.
- Existing configurations render the v0.5.0 homepage unchanged.
