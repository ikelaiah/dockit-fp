# Implementation plan: v0.8.0 visual-system polish

## Task list

### Slice 1: Semantic layout contract

1. Add failing configuration and generated-markup tests for content width.
2. Implement the optional content-width model and validation.
3. Apply semantic width tokens while preserving the current default.

### Slice 2: Theme and component polish

4. Add generated-asset assertions for theme surfaces, focus visibility and
   reduced motion.
5. Refine typography, tables, callouts, code blocks and responsive spacing.
6. Verify keyboard flows and all visual themes in a real browser.

### Slice 3: Fixtures, documentation and release

7. Add and test a maintained long-form visual fixture.
8. Document layout choices and the visual verification matrix.
9. Update version, changelog, roadmap, migration notes and release manifest.
10. Run full automated, documentation, build and review gates.

## Risks and mitigations

| Risk | Mitigation |
| --- | --- |
| Theme-specific CSS breaks colour overrides | Keep shared semantic tokens authoritative and test selector ordering. |
| Wide prose harms readability | Keep `comfortable` as default and constrain paragraph measure independently. |
| Visual polish regresses mobile controls | Verify the fixture at phone, tablet and desktop widths with keyboard checks. |
